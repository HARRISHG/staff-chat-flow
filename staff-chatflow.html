Setup, once

Use the same API block settings as the patient bot. Every call sends the same first two rows; only action and a few extra rows change. phone is always the staff member's own number. When staff act for a patient, the patient's number goes in patient_phone.

n8n always replies {"result": "...", "data": {...}}. Save these fields into bot variables; each step lists the ones it uses.

Staff act on rows by number. Today's visits, the call list and search results arrive as numbered text in {{list_text}}. Staff reply with a row number (item_no), and n8n turns it back into the right visit or person. Today's list keeps done and no-show rows, so its numbers stay the same all day. The call list drops a person once they're logged as done, so its numbers shift: always pick from the list just shown.

    Before you share it with staff

    Anyone who types a staff number gets the staff menu. The web bot can't prove who is typing. Anyone who enters a staff mobile number sees today's patients, names and phone numbers. Until there is a PIN check, keep the staff bot's link private: don't put it on the website, and share it only with your team. A PIN needs a small change in n8n (a pin field on each staff record, checked by the router). WhatsApp fixes this on its own, because there the number comes from WhatsApp instead of being typed.

    Test checklist

    • Staff number 7094596877 (Harrish, owner): G3 returns LIST and you reach the menu.
    • Patient number 9999900001: G3 returns NOT_STAFF, and G4 ends the chat. No lead is created.
    • Today → pick the Demo Patient's visit → Visit done. The reply names the patient, and in the patient bot HELLO now returns REVIEW_DUE.
    • Today → pick a number that isn't on the list → NOT_FOUND message, then back to the list.
    • Call list → pick a call-back request → 4 → BAD_REQUEST message. Requests take only 1, 2 or 3.
    • Call list → 1 (No answer) → 2 (Tomorrow): the person leaves today's call list and comes back tomorrow.
    • Book for patient with a brand-new number: NOT_REGISTERED → name → CREATED → booked at the same time.
    • Book for patient on a time that's already taken: it books anyway. Staff can double-book; patients can't.
    • Find patient with Demo, then with 0001. Both find the Demo Patient with their next visit.
    • Walk-in with an existing number → EXISTS, then the offer to book.

    How this differs from the staff menu inside the patient bot (section 9)

    • Separate bot. Patients never see staff options, and you can keep its link private.
    • The entry check uses S_TODAY instead of HELLO. HELLO turns any unknown number into a new lead. S_TODAY answers NOT_STAFF without creating anything, and it already returns today's count for the greeting.
    • Booking asks what the visit is for. n8n already stores treatment on the appointment.
    • Search results lead somewhere. Staff can book from the results or search again, instead of dropping back to the menu.
    • New Done button to end the chat, plus explicit handling of NOT_STAFF.
